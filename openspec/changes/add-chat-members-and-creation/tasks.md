# Tasks

Each task names the files it owns and what it depends on. Tasks without a dependency between them may run in parallel; a task shares files with every task that edits the same file, so those run in order. Streams that are independent of each other: **P1** (1.x), **P2** (2.1, then 2.2 after 1.3), **G** (0.1). After 3.1 the core stream **C** (3.2 → 3.3) and the UI stream **U** (4.x) overlap as marked. Tasks marked `[approval]` act on the real account and need the user's explicit approval of the target before they start; without it they stay open and block only the archive, not the implementation. A redirect after the creation POST left is therefore a non-success reply (non-JSON body → `Unknown`), never a failed second connection that would read as `NotSent`; regression `manage_never_follows_a_redirect_after_the_request_left`.
