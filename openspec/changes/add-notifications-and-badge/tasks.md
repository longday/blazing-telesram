# Tasks

Legend: **[live]** needs the signed-in session in the VM's `~/bt/.runtime` and the real account; every live task here is **reads only** (nothing is written to the account by this client); live tasks share the one live slot (`DEPENDENCIES.md` rule 5), `BT_WRITE_ONLY_CHAT` stays set. **[needs-user]** needs a person other than the agent: a sender that is not the app account, or a mute toggle in the user's own web session. **[NB-B]** / **[NB-N]** name the merge unit (below). **[after 0.4]** waits for the closed research.

Contracts (types, names, selectors, labels, wording) are fixed in `design.md` D2-D9 and in the two specs, so tasks can be coded against them in parallel. Each task names the files it owns; `DEPENDENCIES.md` rules apply: one owner per file at task granularity, every merge to `main` compiles and passes tests with no stubs and no no-op arms (rule 2), **zero build warnings** and no `#[allow(dead_code)]` (rule 3), cargo, `bt-probe` and the app only in the Tart VM `bt-vm` in the agent's own `~/bt/src-<name>` (rule 4, `docs/vm.md`). Unit tests belong to the task that adds the code, except the shared `desktop/src/tests.rs` (6.1, 6.2). A new `StoreEvent` variant or a changed `Platform` field is found with `lsp` references first and every match updated.

Merge units: **NB-B** (the Dock badge) = 1.1, 2.1, 3.1, 4.1, 6.1 on branch `integ/add-notifications-and-badge`; it needs no research outcome and merges **first**. **NB-N** (notifications) = 1.2, 2.2, 4.2, 5.1, 5.2 (only for R1 outcome 2), 6.2, started **after NB-B is on `main` and after 0.4** (it extends the files NB-B holds: `store.rs`, `alerts.rs`, `desktop.rs`, `main.rs`, `tests.rs`, `Cargo.toml`, `Cargo.lock`). Checks per unit in `bt-vm`: `cargo fmt --all --check`, `cargo build --workspace --all-targets --locked` with zero warnings, `cargo test --workspace --locked`, `cargo clippy --workspace --all-targets --locked` (no new warning over the baseline in `DEPENDENCIES.md`), `openspec validate add-notifications-and-badge --strict`. If R1 ends in outcome 3, NB-N does not start and 4.2, 5.x, 6.2 are struck by 0.4 (the badge unit alone is delivered).

File overlap with other open changes at the time of writing: none in flight (CM has only blocked live tasks 5.1/5.3, PIN only the live 6.2 and the unticked 3.3 already on `main`); whoever starts a file first holds it until its unit merges (rule 6).
