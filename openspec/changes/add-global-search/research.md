### Архитектурный вывод

Локальный поиск уже встроен в UI → `visible_chats`; его расширение для составных фильтров остаётся на стороне desktop/store. Поиск сообщений требует нового типизированного registry-запроса в `yandex-proto`, его проксирования через `chat-core`/backend и UI для асинхронных результатов. Пометка непрочитанным — отдельная write-операция в закрытом `WriteRequest` и `Command`-контуре; сначала нужно подтвердить точную форму и семантику. Папки не следует моделировать как локальные фильтры без протокольного основания: пока неизвестно, серверные они или пользовательские и как сохраняются.

### Рекомендуемое разделение change

1. **Поиск и фильтры:** расширить локальные фильтры; отдельным этапом добавить поиск сообщений/людей/чатов через `search`, включая состояния загрузки, ошибки и пагинацию после уточнения API. Файлы/ссылки из макета можно вынести отдельно: описанный `search` не подтверждает такие категории.
2. **Папки:** отдельное исследование источников и решение о модели/хранении до реализации.
3. **Пометить непрочитанным:** отдельный change после проверки `UnseenMarker` на тестовом аккаунте; не отправлять неизвестный маркер или угадывать поля.

### Открытые решения для пользователя

| Вопрос | Рекомендация | Компромисс |
|---|---|---|
| Нужен ли поиск только по чатам или также по содержимому сообщений? | Считать server-side поиск сообщений частью scope: макет показывает его явно. | Новая сеть/API и сложнее состояния UI; локальный поиск уже работает. |
| Включать ли людей и файлы/ссылки из макета? | Людей включить как отдельный тип результата; файлы/ссылки вынести, пока API-поддержка не подтверждена. | Макет реализуется частично, зато не обещаем неподтверждённый серверный поиск. |

### Риски

- Поиск сообщений отправляет запросы с текстом пользователя на сервер; следует определить, когда выполнять запрос и какие категории/состояния истории он затрагивает.
- `UnseenMarker` меняет состояние аккаунта и может повлиять на другие клиенты; точная необратимость и возможность вернуть прочитанное не установлены. До подтверждения не включать в production writes.
- «Пометить непрочитанным» может конфликтовать с автоматическим `SeenMarker` при открытом чате; UI должен явно определить приоритет и момент сброса.
- Ошибка или догадка в пагинации может пропускать/дублировать результаты; параметр `page` в reference не подтверждён.
